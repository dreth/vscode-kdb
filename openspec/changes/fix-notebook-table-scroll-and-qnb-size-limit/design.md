## Context

The `.qnb` codec accepts a JSON cell array and currently rejects byte buffers above 16 MiB on both decode and encode. First-party MIME v2 output is complete, so a normal query can cross that file limit. The browser notebook renderer owns live and saved table viewports; the KX Results panel has a separate renderer. Live slice refresh replaces canvas children, and saved visible-row auto-fit currently rebuilds the entire result on each newly visible row.

## Goals / Non-Goals

**Goals:** Preserve exact `.qnb` output through large-file save/reopen and keep inline table scroll positions stable through ordinary viewport updates.

**Non-Goals:** Change the `.ipynb` serializer, MIME v1/v2 format, KX Results panel, chart sampling, or the existing structural and privacy validation rules. No new size setting is needed because the fixed file cap is removed.

## Decisions

1. Remove the codec's file-wide byte comparisons on read and write. Keep the same JSON format and all shape, depth, count, MIME, UTF-8, and sanitization checks. This makes one policy for both new and existing `.qnb` files and avoids an arbitrary larger cap or a setting that would still reject valid output.
2. Disable browser scroll anchoring for the live grid viewport while virtual canvas children are replaced. Retain the physical vertical and horizontal offsets when applying slice updates; the existing row-window and full-height canvas remain the sources for displayed rows. This prevents browser anchoring from interpreting virtual row replacement as a reason to move the viewport.
3. For saved visible-row auto-fit, update the current table's column widths in place as the viewport crosses rows. The table already contains its bounded page; replacing the whole result on every scroll row also replaces the viewport and can interrupt wheel scrolling. Other state changes continue through the existing full render path, which captures and restores viewport state.
4. Serialize compact JSON while retaining the compatible cell-array format and trailing newline. A local 60,000-row, 8-column typed fixture expanded from 36.8 MiB MIME to 120.4 MiB indented `.qnb` and spent 2.7 seconds serializing, versus 0.1 seconds writing locally. Compact JSON reduces bytes and allocation without dropping data. The notebook serializer owns its freshly parsed MIME output objects, so it can skip a second full deep copy during encoding. The generic codec keeps its default value-copy normalization; structural validation remains active on both paths.

5. The actual `kind_rosalind` remote extension host crashed with a 4 GiB V8 heap exhaustion during the user's save (2026-10-01 07:10 UTC); the cancellation was reported after the crash. This establishes memory exhaustion, not the exact allocating caller. Native stack addresses resolve to JSON parsing. VS Code's real `NotebookCellOutputItem.json` indents with tabs, unlike our compact mocks. Emit compact JSON via the text factory using the same MIME; validate/minify existing JSON output with a bounded-depth scanner and splice its validated text into the compatible `.qnb` envelope without parsing all typed nodes. Keep the generic object codec normalization, metadata sanitization, malformed-JSON fallback, finite-number/key-length/depth checks, UTF-8 checks, and legacy sidecar behavior. Add content-free save diagnostics to distinguish serializer work from subsequent host transfer/write. Test realistic pretty MIME, constrained heap, repeated saves, and exact reopen; no claim that synthetic timing proves the user's real save succeeds.

6. The installed 0.2.37 serializer completed the user's 77 MiB output in 3.6 seconds, but the host again exhausted its heap before writing. Runtime stack capture identifies complete MIME JSON parsing in live scroll authorization and output reconciliation. Cache only a validation proof and an owned byte snapshot, never the parsed result tree. A hit requires exact native byte comparison, fresh strict direct/nested metadata validation, and unchanged payload identity. Keep duplicate MIME/output claims, bounded scans, and notebook/cell/live-store ownership checks. Value-backed mutable output uses the canonical parser. Bound snapshot storage to 128 MiB/32 entries, permitting one larger current output rather than imposing a result-size cap; clear on close/dispose. Explicit saved-result actions retain full parsing. Before validating a live candidate, filter using all canonical direct/nested claimed binding IDs: unrelated claims cannot authorize or invalidate the requested output. Retain the complete bounded scan and malformed matching claims. This avoids parsing unrelated large cells and evicting the requested proof. Cover mutation, stale/foreign ownership, and repeated live slices during save, then verify the actual running Dev Container handler.

## Risks / Trade-offs

- Large `.qnb` files require memory and time to parse, encode, and save → document this cost and leave host allocation or filesystem failures visible rather than claim a complete save.
- Browser scroll anchoring differs across VS Code runtimes → add a source-level regression plus an extension-host visual check for live and saved scroll stability; run the available unit suite in this environment.
- In-place saved width updates may expose stale widths after another table state change → retain the existing full render on sort, page, column, and settings actions and test the visible-row path specifically.
